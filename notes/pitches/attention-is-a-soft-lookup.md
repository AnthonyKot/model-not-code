# attention-is-a-soft-lookup — pitches (2026-09-12)

**Working title:** Attention Is a Dictionary Lookup That Returns a Weighted Mix
**Mechanism (catalog):** Scaled query·key scores, softmaxed, weight the values; a causal mask hides the future.

## Pitch A — a lookup that never misses, because it returns a blend

You know what a dictionary lookup is, so when a paper says the model "attends to" the relevant word you either picture an exact-match fetch or you picture magic, and neither explains why changing one word far back in a prompt shifts the answer a little rather than not at all. The essay explains attention as a lookup with the equality test replaced by a score: the query vector is dotted with every key vector, the scores are divided by the square root of the key length, the softmax turns them into positive weights that sum to one, and the result is the values added up under those weights — so instead of one entry you get a mix in which the best match dominates and the rest still contribute; the essay then shows that scaling the scores up sharpens the mix toward an exact fetch and scaling them down flattens it toward an average, which is why the square-root divisor exists. The worked example (invented) has three stored entries with four-number keys, two-number values (1,0), (0,1) and (1,1), and a query whose raw dot products with the keys are 4, 0 and 2: divided by √4 they become 2, 0 and 1, the softmax gives weights 0.665, 0.090 and 0.245, and the output is 0.665·(1,0) + 0.090·(0,1) + 0.245·(1,1) = (0.910, 0.335), against the (1,0) a hard lookup would have returned. The exercise is the same lookup in twenty lines with nothing but `exp`, first reproducing (0.910, 0.335), then multiplying the three scores by ten to obtain weights of 0.99995, near 0 and 0.00005 — a soft lookup that has become a hard one — so that the reader can predict, from the spread of scores alone, whether a head behaves like a fetch or like an average.

Draws on: course-6538601/02-02, course-4735368/28-02, course-6100015/03-18; supporting book: Raschka, *Build a Large Language Model (From Scratch)* (`raschka-qai`).

## Pitch B — the mask is what makes training and generation the same program

You are told the model was trained on whole documents, including the tokens it is later asked to predict, and that at serving time it produces one token at a time, and you cannot see why those two are the same computation or why the training pass is not simply cheating. The essay builds the full score table — every token's query against every token's key, a square matrix the size of the sequence — and then shows the causal mask: every entry above the diagonal is set to a very large negative number before the softmax so its weight comes out as zero, which means position k's output depends only on positions 1 to k, and appending a new token to the sequence leaves every earlier row's numbers exactly as they were; that invariance is what lets one forward pass over a document score every next-token prediction at once, and lets generation reuse the earlier rows unchanged. The worked example (invented) is three tokens with the same toy keys and values as Pitch A: row 2's scaled scores are 0 and 2 against the first two keys, masked to nothing against the third, giving weights 0.119, 0.881, 0 and an output of (0.119, 0.881) — and the essay recomputes the same row with only two tokens present, obtaining the identical (0.119, 0.881), then without the mask, obtaining weights 0.107, 0.787, 0.107 and a different output (0.213, 0.893). The exercise is the square-matrix version in thirty lines: build the table for three tokens, mask it, take the row-wise softmax, and then add a fourth token and assert that rows 1 to 3 do not change — the expected result is a passing assertion with the mask and a failing one without it, plus the reader's own statement of why "the model saw the future during training" is false.

Draws on: course-4735368/28-02, course-6538601/02-02; supporting book: Raschka, *Build a Large Language Model (From Scratch)* (`raschka-qai`).

## Pitch C — the square table is where the time goes

You double a prompt's length and the latency does not double, and you want to know which part of the computation is quadratic and which part the parameter count actually lives in before you argue about context limits with anyone. The essay walks the shapes: the input is S tokens of width d_model, three learned matrices project it to queries, keys and values of width d_k (a linear cost in S, and the only place parameters live — none of them depend on S), the score table is S × S (quadratic), the softmax and the weighted sum of values are S × S again, and the causal mask hides the future without saving work in the plain implementation, since the masked half is computed and then discarded; multi-head attention repeats this with d_model split across heads and concatenated back. The worked example (invented) takes S = 5, d_model = 8 and d_k = 4 for one head: the three projections cost 5·8·4·3 = 480 multiplications, the score table 5·5·4 = 100, the mix 100; at S = 10 those become 960, 400 and 400, and at S = 12 the two quadratic terms (576 + 576) equal the projections — the crossover sits at S = 1.5·d_model whatever the numbers, which the reader can derive in one line; the parameters meanwhile are 3·8·4 = 96 per head and stay 96 at any S. The exercise is a ten-line cost counter over (S, d_model, d_k, heads) that prints the linear and quadratic terms and the crossover; the expected result is the three rows above and, run with the head count and width of any published model card, a number of tokens beyond which the score table, not the projections, is what the reader is paying for.

Draws on: course-4735368/28-02, course-6538601/02-02, course-6100015/03-18; supporting book: Raschka, *Build a Large Language Model (From Scratch)* (`raschka-qai`).

## Note on sources

All three cited lectures carry attention material, at three depths. `course-4735368/28-02` is the fullest: the search-engine analogy for query, key and value; the S × d and d × S shapes giving an S × S table (its own example is 5 × 32); scaling by the square root of d_k; a row-wise softmax worked with `e^0.6` and neighbours; the weighted sum with V; multi-head projections, concatenation and the output projection; residual add and layer norm versus batch norm; the feed-forward block; sinusoidal positions; and the causal mask, described as zeroing the weights of future positions so that each output depends on itself and earlier tokens only. `course-6538601/02-02` covers the same chain more briefly (one-hot → embedding → Q, K, V → scaled dot product → softmax → weighted values, multi-head, positional encoding) and explicitly skips the mask as "optional", so it supports Pitches A and C and only the unmasked half of Pitch B. `course-6100015/03-18` is an intuition tour of a Llama decoder layer (query, key, value and output as the four learned parameter sets; up-, gate- and down-projections; why a non-linearity is needed) with no arithmetic; it is a fair supporting source for the "learned matrices, independent of sequence length" point in Pitch C and for naming the four projections in Pitch A, not for the worked examples. Real figures in these lectures — d_model 512, eight heads, d_k 64, feed-forward width 2,048, six blocks, a 2,048-wide Llama layer with sixteen decoder blocks — are the lecturers' reports of the papers and models and would be written "as reported in the lecture"; the worked examples above use only the book's own numbers, verified by running the toy computation, and the mask's implementation as a large negative number before the softmax (rather than the lecture's zeroed weights) is the book's own restatement, to be checked against the supporting book at drafting time.

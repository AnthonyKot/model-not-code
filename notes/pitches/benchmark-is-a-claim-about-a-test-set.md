# benchmark-is-a-claim-about-a-test-set — pitches (2026-09-13)

**Working title:** A Benchmark Score Is a Claim About Someone Else's Test Set
**Mechanism (catalog):** A public benchmark number is evidence only about its test set: selection on a fixed public set inflates it, contamination is the extreme case, and a private once-used set with blind pairwise comparison is the defence.
**Boundary with `validation-set-is-a-budget` (published).** That essay is about *your own* splits: it derives the standard error of an accuracy (√(p(1 − p)/n)), enumerates best-of-N on your validation set, and simulates spending your test set. This essay starts from a number *someone else published* on a fixed, public item set that you cannot re-split, re-sample or inspect per item. It may use the standard error in one callback sentence and must not re-derive it or re-run the best-of-N simulation; what it adds is what can be read out of a leaderboard table (paired gaps, how many entries were tried on the same items), what happens when the items themselves leaked, and how to build the replacement evidence.

## Pitch A — a leaderboard gap is a claim about the same 448 questions (recommended)

You are choosing a model from a leaderboard where the top entry beats the second by two points on a 448-question benchmark, and you are about to pay for that difference — but the two points are a difference between two counts on one fixed set of questions that every entrant has been tuned against, and the table does not tell you whether it would survive a different 448. The essay explains how to read a public score as evidence: (1) a score is a count of solved items on a fixed set, so it describes those items and, through them, a population of similar questions only up to sampling noise; (2) because every model answers the same items, the noise in a *gap* depends on the items where exactly one of the two models is right — with b items only A solves and c only B solves, the gap's standard error in items is √(b + c − (b − c)²/n), so the same headline gap can be decisive or meaningless; (3) the top row of a table is the maximum over many entries, checkpoints and prompt variants scored on those same public items, so it carries a selection bonus a reader cannot see but can bound from the number of entries; (4) the defence is a set that was not available to select on: a rewritten or private set, used once. The worked example (invented, on a set the size of one real hard benchmark) has model A at 278/448 = 62.05% and model B at 268/448 = 59.82%, a gap of 10 questions: if they disagree on 60 questions (35 only A, 25 only B) the gap's standard error is √(60 − 100/448) = 7.73 questions, and the gap is 1.29 standard errors — not distinguishable; if they disagree on only 14 (12 and 2) it is √(14 − 100/448) = 3.71 questions and the same 10-question gap is 2.69 standard errors; and if the table holds ten entries whose true accuracy is all 60%, the expected top score is 284.7/448 = 63.5% (computed exactly from the binomial distribution), 3.5 points above every one of them. The exercise is PyTorch: simulate a 448-item benchmark with a shared per-item difficulty (so models agree on easy and hard items), twelve models whose true skills differ by 0.02 in log-odds from one to the next, print the top two public scores with their unpaired and paired standard errors, then draw 1,000 fresh 448-item sets and count how often each model tops the table; `workspace/benchmark-is-a-claim-about-a-test-set/proto_a.py` prints `public top two: 7 0.5625 3 0.5513`, `gap 0.0112 only-a 62 only-b 57 SE unpaired 0.0332 SE paired 0.0243`, true order `[11, 10, 9]`, and shares of first place that rise from 0.01 for the weakest model to only 0.221 for the truly strongest — the public winner (model 7) is truly only the fifth-best, and the truly best model tops fewer than one fresh set in four.

## Pitch B — contamination is a score for remembering, and rewriting the questions measures it

A model's announcement quotes 70% on a public benchmark, your internal questions of the same kind come back at 64%, and you cannot tell whether your questions are harder or the benchmark's answers were in the model's training data — the published number cannot distinguish solving a question from having seen it. The essay explains contamination as selection taken to its limit: (1) public items are text on the web, and a training crawl that reaches them trains on the answer key; (2) the score then mixes two things — the fraction f of items answered from memory (right almost regardless of skill) and the skill q on the rest, score ≈ f + (1 − f)·q; (3) rewriting each item so that the facts, names or numbers change while the reasoning stays the same removes the memory term and leaves q; (4) so the drop from original to rewritten, divided by (1 − q), estimates f — and a private set, never published, is the only version where f is zero by construction; with the training corpus in hand, the check is overlap between benchmark chunks and training chunks above a threshold. The worked example (invented) takes 448 items, a leaked fraction f = 0.2 (about 90 items) and a true skill q = 0.625: the published score is 0.2 + 0.8 × 0.625 = 0.70, the rewritten set returns 0.625, the drop is 0.2 × (1 − 0.625) = 0.075, and dividing the drop by 1 − 0.625 = 0.375 recovers f = 0.2 — the same 70% from a model with q = 0.70 and no leak would show no drop at all. The exercise is PyTorch: a 20-feature synthetic "question" whose answer follows a linear rule except for 20% of items whose answers need more than the rule, a 448-item public set, a 448-item rewritten set drawn the same way, and two identical MLPs trained on 2,000 items — one clean, one with 90 public items copied five times into its training data; `workspace/benchmark-is-a-claim-about-a-test-set/proto_b.py` prints `clean public 0.661 rewritten 0.676 leaked items 0.689` and `contaminated public 0.705 rewritten 0.643 leaked items 1.000`, so the drop of 0.062 divided by 1 − 0.643 estimates f ≈ 0.17 against the true 90/448 = 0.20, while the clean model shows no drop.

## Pitch C — when there is no answer key, count blind wins

Your task — summarising support tickets, drafting replies — has no multiple-choice key, the arena leaderboard ranks two candidates five rating points apart, and you need to know which to deploy on your prompts, not on the arena's. The essay explains the pairwise defence: (1) show the same prompt's two outputs side by side with the model names hidden and record which is preferred; (2) a rating model turns win rates into a scale: with ratings r<sub>A</sub> and r<sub>B</sub>, P(A preferred) = 1 / (1 + 10<sup>(r<sub>B</sub> − r<sub>A</sub>)/400</sup>), and fitting ratings to many such outcomes is logistic regression on rating differences (Bradley–Terry); (3) a win rate from m comparisons is a proportion with standard error √(w(1 − w)/m), so the rating gap it supports has an interval that m controls; (4) the prompts are your own and unpublished, scored once for this decision, so nothing was selected on them and nothing leaked. The worked example (invented except for the rating formula) starts from two ratings 100 points apart: 1/(1 + 10<sup>−100/400</sup>) = 0.640, a 64% preference; five points apart gives 0.507, and telling 50.7% from 50% at two standard errors needs (2 × 0.5 / 0.0072)² ≈ 19,300 votes; on your own 200 blind comparisons, 120 wins give w = 0.60 with standard error 0.0346, a 95% range of 0.532 to 0.668, which the formula turns into a rating gap of 400·log<sub>10</sub>(0.6/0.4) = 70 points with a range from about 22 to 121. The exercise is PyTorch: four candidates with true ratings 0, 20, 70 and 75, simulated blind votes on every pair, ratings fitted by gradient descent on the Bradley–Terry log-likelihood, repeated 100 times at 50 and at 2,000 votes per pair; `workspace/benchmark-is-a-claim-about-a-test-set/proto_c.py` (about 20 seconds on one CPU thread) prints `50 votes per pair: last fit [0, 7, 74, 88], model 2 ranked above model 3 in 34 of 100 runs` and `2000 votes per pair: last fit [0, 13, 64, 70], model 2 ranked above model 3 in 14 of 100 runs` — the 50-to-70-point gap between the two pairs of models shows in both printed fits, while the 5-point gap between models 2 and 3 is still reversed in 14 runs of 100 after 12,000 votes in total.

# class-imbalance-changes-the-loss — pitches (2026-09-12)

**Working title:** 95% Accuracy on a 95/5 Dataset Is the Baseline, Not a Result
**Mechanism (catalog):** Class weights or resampling change how much loss each class contributes; the confusion matrix shows per-class recall.

## Pitch A — the loss is a sum, and the majority class owns the sum

Your classifier reports 95% accuracy on a dataset that is 95% negatives, which is exactly what a function returning `false` scores, and you shipped it because the metric looked like a result. The essay explains one mechanism: the training loss is a sum over examples, so on a 95/5 split the majority class contributes nineteen loss terms for every one the minority contributes and the gradient points wherever the majority points; a per-class weight multiplies each example's loss term, and choosing weights inversely proportional to class count makes the two classes' total contributions equal, which is the same thing as changing the question the optimiser is answering. The worked example (invented) is 100 rows, 95 negative and 5 positive: the reader computes the inverse-frequency weights scaled by the row count (100/95 ≈ 1.05 and 100/5 = 20), checks that 95 × 1.05 and 5 × 20 both come to 100, and then computes the best constant predictor under cross-entropy both ways — the probability that minimises unweighted loss is the base rate 0.05, and under the equalised weights it is 0.5 — so a model trained with weights is being pushed to a different answer, not just a louder one, and its accuracy on the unweighted test set will fall while minority recall rises. The exercise is a spreadsheet or ten lines of any language: for the same 95/5 rows, tabulate the log loss of constant predictors p = 0.05, 0.2, 0.5 and 0.8 with and without the weights; the expected result is that the unweighted column is lowest at 0.05 and the weighted column at 0.5, and the reader can then try the lecture's counts as reported (three classes of 1,525, 3,019 and 2,255) and recover weights in the same ratio as the ones the lecturer reports.

Draws on: course-4735368/15-02 (loss penalised more for the under-represented class; weights as 1/count scaled by the total; reported counts and reported weights 4.45, 2.25, 3.01; the lecturer's advice to balance the data first), course-4735368/06-02 (accuracy treats false negatives and false positives alike, which is why it cannot show the imbalance). Supporting book: Huyen, *Designing Machine Learning Systems* (class imbalance chapter: cost-sensitive learning, focal loss).

## Pitch B — read the rows of the confusion matrix, not the diagonal

You have a three-class model at 85% accuracy and a user complaint that "it never gets the rare one right", and both are true at once, because accuracy is one number over the diagonal while the damage is in one row. The essay explains the confusion matrix as a table of counts you read by row — each row's diagonal share is that class's recall, and the row for the smallest class is where an imbalanced training set puts its mistakes — then shows how per-class loss weights move errors between rows, with the lecture's reported before-and-after (errors concentrated on the smallest of three classes, then spread more evenly after weighting at a reported 84% accuracy) as the shape to expect, and macro-averaged recall as the single number that does not let the big row hide the small one. The worked example (invented) is a 200-row test set with 20/120/60 true labels and a matrix in which the rare class gets 8 right, the big class 114 and the middle class 48: the reader computes accuracy (170/200 = 85%), per-class recall (40%, 95%, 80%) and macro recall (71.7%), then a second matrix after weighting with 14, 102 and 47 right, and finds accuracy fell to 81.5% while macro recall rose to 77.8% — the two numbers moved in opposite directions and only one of them answers the complaint. The exercise is two invented confusion matrices given in the essay plus a stated cost per error type; the reader computes accuracy, each class's recall and macro recall for both, and picks one; the expected result is that the higher-accuracy matrix loses on macro recall and on the cost total, and that a third matrix the reader builds by hand can raise the rare class's recall to 100% only by sacrificing the big class — which is the trade the weights are making.

Draws on: course-4735368/15-02 (three-class confusion matrix read row by row; reported per-row error counts before and after class weighting), course-4735368/06-03 (building a confusion matrix from labels and predictions; what each cell counts), course-4735368/06-02 (precision, recall and accuracy formulas from the four cells; why one error type may cost more than the other). Supporting book: Huyen, *Designing Machine Learning Systems* (evaluation metrics under imbalance).

## Pitch C — resampling is weighting with a leak attached

You fixed the imbalance by oversampling the positives before splitting, your validation recall went to 98%, and the production model is no better than before, because copies of the same positive row landed on both sides of the split and the validation set was grading the model on rows it had memorised. The essay explains one equivalence and its consequence: duplicating an example k times in the training set and multiplying its loss term by k are the same change to the summed loss, so oversampling, undersampling and class weights are one mechanism at three prices — undersampling discards the majority rows you paid for, oversampling copies rows and any copy that crosses the split is a leak, weighting keeps every row and touches only the loss — which is why the split must happen before any resampling. The worked example (invented) is 100 rows, 5 positive: oversampling the positives nineteen-fold yields 190 rows and the same per-epoch loss total as weight 19 on the original 5; undersampling yields 10 rows and throws away 90; and if the 190 rows are shuffled and split 80/20, the reader computes that a given positive's twenty copies all land on one side with probability 0.8^19 + 0.2^19 ≈ 0.014, so about 99 in 100 positives have a twin in both sets. The exercise is fifteen lines of any language with a random generator: label 100 rows, mark 5 positive, oversample them, shuffle, split 80/20 and count validation positives that share an id with a training row; the expected result is nearly all of them, and repeating with the split done first and oversampling applied to the training side only gives zero, which is the order the reader takes back to their pipeline.

Draws on: course-4735368/15-02 (random oversampling and undersampling described; the lecturer's caution against both; class weights as the alternative), course-4735368/06-03 (per-cell counts, so the reader can see where leaked copies would show up as true positives). Supporting book: Huyen, *Designing Machine Learning Systems* (resampling before versus after splitting; data leakage).

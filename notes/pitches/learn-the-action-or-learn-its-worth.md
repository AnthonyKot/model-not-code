# learn-the-action-or-learn-its-worth — pitches (2026-09-12)

**Working title:** Learn What To Do, or Learn What It Is Worth
**Mechanism (catalog):** Value methods estimate returns and act greedily; policy-gradient methods move action probabilities in proportion to return.

## Pitch A — one family flips, the other slides

Your value-based agent's behaviour changes all at once — when two estimated returns cross, the chosen action jumps from never to always — and it cannot express "do this 70% of the time", which is the right answer in any game where you do not see everything. The essay explains the two families as two objects the network outputs: a table of expected returns per action, read with an argmax (so the policy is a step function of the estimates), or a probability per action from a softmax, moved by an update that adds return × ∇log π to the parameters (so the policy is a continuous function of them) — and works the update through once so the reader can see the slide. The worked example (invented) is one state with two actions: under the value method the estimates 5.0 and 5.1 select B every time and a single noisy update to 5.2 and 5.1 selects A every time; under the policy method logits 1.0 and 1.1 give probabilities 0.475 and 0.525, and one REINFORCE step after action B returned +2 with learning rate 0.1 changes the logits by ±0.095 (the reader computes 1 − π(B) = 0.475 as the gradient of log π(B) with respect to its own logit), moving B's probability from 0.525 to 0.572 — a nudge, not a flip. The exercise is numpy on a two-armed bandit (arm A pays 1 with probability 0.6, arm B with 0.4): run 2,000 pulls with an ε-greedy value table and with a softmax policy trained by the one-line REINFORCE update, recording the probability of choosing A each pull; the expected result is a staircase for the value agent (jumping between 0.05 and 0.95 as the estimates cross early on) and a smooth curve for the policy agent, both ending near A, which is the picture the reader keeps when choosing a family for a task with hidden information.

Draws on: course-3725442/11-01 (a network that outputs action probabilities; stochastic policies for imperfect information, the reported 70/30 example; gradual change versus the 0-to-100% switch of a greedy policy), course-3725442/11-02 (softmax output; reported example vectors), course-3725442/11-05 (the REINFORCE update: return times the gradient of the log-probability), course-3725442/05-08 (a greedy target policy that always takes the highest estimated value). Supporting book: Lapan, *Deep Reinforcement Learning Hands-On* (policy gradients chapter for the update in code).

## Pitch B — one family measures the return, the other bootstraps it from its own guess

Your deep Q-learner's loss oscillates and drifts on a task where the same network fits a supervised dataset without trouble, because the regression target it is fitting contains its own output — and a target that moves when you move toward it is what the value family has to tame. The essay explains the difference by what stands in for "the return" in each update: REINFORCE waits for the episode to end and uses the measured discounted sum (unbiased, noisy, one update per episode), while Q-learning writes the target as reward plus γ times its own best estimate of the next state (biased while the estimates are wrong, available every step), then shows why the second needs a replay memory and a frozen target copy once the table becomes a network — updating one state's estimate moves its neighbours' estimates, so the target chases itself. The worked example (invented) is a four-step episode with rewards 0, 0, 0, 1 and γ = 0.9: the reader computes the four Monte-Carlo returns 0.729, 0.81, 0.9 and 1.0, then runs tabular Q-learning with learning rate 1 from a zero table and tabulates the values after episodes one to four — the reward appears at the last state after episode one, at the third after episode two, and reaches the start only after episode four, at exactly 0.729 — the same numbers arriving one state per episode instead of all at once. The exercise is numpy: a five-state corridor with a reward of 1 at the end, tabular Q-learning with α = 0.5 and ε = 0.1 against a first-visit Monte-Carlo estimate of the start state's value; the expected result is that the Q table needs at least four episodes before the start state is non-zero and more to reach within 10% of 0.9⁴ ≈ 0.656, while the Monte-Carlo estimate is unbiased from the first successful episode and noisier — a bias-versus-variance trade the reader has now measured rather than read about.

Draws on: course-3725442/05-08 (Q-learning as off-policy: a greedy target policy, an exploratory behaviour policy, the update using the target policy's next action), course-3725442/11-05 (REINFORCE as a Monte-Carlo method: the actual return with no bootstrapping; the γᵗ weighting of early actions), course-3725442/09-04 (bootstrapping plus a function approximator gives a moving target; the frozen target network synchronised every K episodes), course-3725442/09-03 (replay memory: a bounded store of transitions sampled at random for each update), course-3725442/11-04 (the policy-gradient theorem stated in words: gradient proportional to return times the gradient of the action's probability, weighted by state frequency). Supporting book: Lapan, *Deep Reinforcement Learning Hands-On* (the Q-learning update rule and DQN chapters, for the formula the lecture shows only on a slide).

## Pitch C — the division by π(a|s) is what keeps the rich from getting richer

Your policy-gradient agent's probability for one action ran to nearly 1 within the first hundred episodes and it stopped exploring, although the other action was just as good — and the fix is a factor already in the REINFORCE update that your implementation dropped. The essay explains why the update is return × ∇π / π (equivalently return × ∇log π) and not return × ∇π: an action taken with probability 0.9 gets updated nine times as often as one taken with probability 0.1, so without the division the frequent action is credited nine times as much for the same return; the division is an importance weight for "how often this sample occurs", which is also why REINFORCE must learn from its own fresh samples while Q-learning, whose target uses the greedy max rather than the action actually taken, can learn from any behaviour policy and hence from a replay memory — the difference that opens the door to PPO's ratio in the next essay. The worked example (invented) is two actions with probabilities 0.9 and 0.1 that both return +1 whenever taken: over ten episodes A is taken about nine times and B once, so the raw pushes total 9 versus 1 while the weighted pushes total 9 × (1/0.9) = 10 versus 1 × (1/0.1) = 10, and the reader confirms the same balance in logit form — the gradient of log π for the taken action's own logit is 1 − π(a), which is 0.1 for A and 0.9 for B. The exercise is numpy: a two-action softmax policy with both actions rewarded +1, run 1,000 updates with the ∇π rule and with the ∇log π rule; the expected result is that the first drifts the initially favoured action toward probability 1 (the expected change in its logit is π_A π_B (π_A − π_B) > 0 per step, which the reader can derive), while the second wanders by noise around its starting point because its expected update is zero — a two-line demonstration of why the log is there.

Draws on: course-3725442/11-05 (dividing the gradient by the action's probability so that frequently chosen actions are not updated too often; the identity ∇π / π = ∇log π), course-3725442/05-08 (off-policy learning: behaviour policy for data, greedy target policy for the update), course-3725442/09-03 (replay memory as reuse of stored transitions, which the off-policy target permits), course-3725442/11-01 (probabilities that rise and fall gradually with results). Supporting book: Lapan, *Deep Reinforcement Learning Hands-On*.
